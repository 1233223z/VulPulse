# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.9.0] - 2026-11-26

### Added

- `X-Request-ID` on every HTTP response and request-scoped debug/error logs.
- Architecture documentation covering data flow, merge policy, scheduling,
  plugins, security boundaries, failure modes and the scaling path.
- `scripts/benchmark_api.py` plus a README performance section with reproducible
  read-only benchmark results.
- CI coverage gate at 75% (`pytest --cov=vulpulse --cov-fail-under=75`);
  the Python 3.14 suite currently measures about 83%.

### Changed

- API observability now records request IDs alongside latency and metrics.

## [0.8.0] - 2026-11-26

### Added

- Prometheus metrics at `/metrics` with bounded route-template labels,
  request counters, latency histograms and `X-Response-Time-ms` response
  headers.
- `VULPULSE_METRICS_ENABLED` to disable the metrics endpoint.
- Documentation for scraping, PromQL examples and metrics endpoint security.

### Changed

- `prometheus-client` is now a runtime dependency; all deployment paths install
  it through the hash-locked requirements files.

## [0.7.0] - 2026-11-26

### Added

- Bounded vulnerability relationship graph centered on a CVE: affected
  products, CWE weaknesses, source records and related vulnerabilities sharing
  a displayed product or CWE.
- `GET /api/v1/vulns/{cve_or_id}/graph` with a configurable related-node limit.
- Offline server-rendered SVG graph page linked from every vulnerability detail
  page, with node risk colors, tooltips, legends and JSON export.
- Related-vulnerability lookup ordered by risk score.

### Changed

- The graph is deliberately capped by product, CWE, source and related-CVE
  counts so a single hub vulnerability cannot produce an unbounded response.

## [0.6.0] - 2026-11-26

### Added

- Source plugin API: any `BaseSource` subclass can be exposed through a
  `vulpulse.sources` entry point and used by the CLI, admin API and scheduler.
- `vulpulse plugins` and `GET /api/v1/plugins` show plugin metadata, schedules
  and load failures.
- Built-in NVD, CISA KEV and Exploit-DB sources now expose plugin metadata and
  scheduling policies through the same interface.
- The scheduler creates one `crawl:<plugin>` job per loaded plugin, so new
  sources do not require changes to the scheduler.
- Installable example plugin under `examples/plugins/vulpulse-example-source`.
- `VULPULSE_PLUGINS_ENABLED` disables third-party plugin discovery while
  keeping built-in sources.

### Changed

- Pinned plugin API version (`PLUGIN_API_VERSION=1`) with clean failure
  isolation for import errors, invalid versions and broken factories.
- Added plugin source documentation and the example plugin to the README.

## [0.5.3] - 2026-11-26

### Added

- Per-client-IP API rate limiting (120 requests/minute by default) with
  `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `429 Retry-After` responses.
  `VULPULSE_API_RATE_LIMIT_PER_MINUTE=0` disables it.
- `VULPULSE_TRUSTED_PROXIES` for reverse-proxy CIDRs. `X-Forwarded-For` is only
  honored when the immediate peer is trusted, and is walked right-to-left so
  clients cannot spoof an address.
- `VULPULSE_DOCS_ENABLED` to control Swagger UI and the OpenAPI schema; both are
  disabled in `prod` by default.
- `scripts/update_locks.py` and generated `requirements.txt` /
  `requirements-dev.txt` hash-pinned locks for reproducible installs.

### Security

- Docker and CI install dependencies with `--require-hashes`.
- GitHub Actions are pinned to commit SHAs and the Docker base image/syntax
  frontend are pinned by digest.
- `SECURITY.md` now documents trust boundaries, controls and residual risks.

### Fixed

- Universal requirement locks are now resolved against Python 3.10, so
  `pip install --require-hashes` works on every supported Python version.
  FastAPI/Starlette use Python-version markers where upstream dropped 3.10.

### Changed

- Crawler `User-Agent` now reflects the running VulPulse version.
- Source distribution requirements remain in `pyproject.toml`; the
  `requirements*.txt` files are generated by uv and should not be edited by hand.

## [0.5.2] - 2026-11-25

### Fixed

- Crawler responses are streamed with a 64 MiB cap; redirects are restricted
  to the same HTTPS host and a maximum of three hops, preventing redirect-based
  SSRF and memory exhaustion. EPSS gzip decompression has the same cap.
- Fixed double gzip decoding in the shared HTTP client introduced by bounded
  streaming.
- Updated the default EPSS URL to its final HTTPS host, avoiding the old
  cross-domain redirect chain.

### Changed

- Docker Compose credentials are scoped to the services that need them; the
  migration service no longer receives API, webhook or SMTP secrets.

## [0.5.1] - 2026-11-25

### Fixed

- SMTP STARTTLS and SMTPS now use `ssl.create_default_context()` so server
  certificates and hostnames are verified; this protects SMTP credentials from
  network attackers.
- WeCom webhooks must use HTTPS and an allowlisted host
  (`VULPULSE_WECOM_ALLOWED_HOSTS`), preventing admin-configured SSRF. Delivery
  errors and HTTP client logs no longer include the webhook URL or key.
- Admin login is rate-limited per client IP and globally, and non-ASCII API keys
  fail cleanly instead of raising a 500.
- Admin sessions expire after eight hours and are bound to a fingerprint of the
  API key; rotating the key invalidates existing sessions.
- Escaped Markdown metacharacters in report identifiers, titles and filter
  descriptions to prevent link and raw-HTML injection in exported Markdown.
- Removed a production `assert` and upgraded pytest to `>=9.0.3` for
  CVE-2025-71176 (development dependency).

### Changed

- `vulpulse serve` now binds to `127.0.0.1` by default. Pass
  `--host 0.0.0.0` explicitly for LAN or container access.
- Admin responses send `Cache-Control: no-store` and all responses send a
  restrictive `Permissions-Policy`.
- Data and log directories are created with owner-only (`0700`) permissions.
- Docker builds use longer pip timeouts and retries.

### Security

- Added an OSV dependency audit script and CI job, plus Dependabot for pip,
  GitHub Actions and Docker.

## [0.5.0] - 2026-11-25

### Added

- Admin web UI at `/admin` with sign-in using the existing `VULPULSE_API_KEY`.
- CSRF-protected forms for creating, enabling, disabling and deleting WeCom/email
  channels and alert subscriptions.
- Subscription forms covering severities, keywords, vendors, products, sources,
  KEV, public exploits, CVSS, EPSS and publication-window filters.
- Configurable session signing secret and HTTPS-only session cookies.

### Security

- Signed, HttpOnly, SameSite=Lax session cookies and per-session CSRF tokens.
- Open-redirect protection for post-login destinations.
- Admin UI is disabled when no API key is configured.

## [0.4.0] - 2026-11-25

### Added

- Filterable Markdown and HTML vulnerability reports with summary cards,
  risk/KEV/exploit columns and safe escaping of untrusted fields.
- `vulpulse export` CLI with the same filters as the query API.
- `GET /api/v1/export` returning the report as a downloadable attachment.
- Export MD / Export HTML buttons on the vulnerability list that preserve the
  active filters.

## [0.3.0] - 2026-11-25

### Added

- Vendor aggregation API (`/api/v1/vendors`) with product counts, risk-level
  breakdowns and average/max risk.
- Vendor detail API (`/api/v1/vendors/{vendor}`) with correlated products and
  top-risk vulnerabilities.
- Vendor and product analytics pages in the web dashboard, plus links between
  vendor, product and vulnerability views.
- Product filtering on vulnerability list endpoints (`product=...`).
- Risk badges on vendor pages and product links in vulnerability details.

## [0.2.0] - 2026-11-25

### Added

- Explainable 0-100 risk scoring combining CVSS, EPSS, CISA KEV, public exploit
  availability and recency, with configurable and normalized weights.
- `risk_score` and `risk_level` columns, an Alembic migration and a `vulpulse
  score` backfill/refresh command.
- Risk scoring on ingest, after EPSS enrichment and in a scheduled
  `score:refresh` worker job.
- API fields `risk_score` / `risk_level` / `risk_breakdown`, a `risk_min` filter
  and `sort=risk_score`; statistics now include risk-level counts.
- Risk column and full component breakdown in the web dashboard.

## [0.1.1] - 2026-11-25

### Fixed

- Serialized scheduled jobs inside the worker, preventing concurrent SQLite
  writers from failing with `database is locked` when several sources start at
  the same time.
- Raised the SQLite busy timeout from 5s to 30s for short API/worker contention.
- Verified the full Docker Compose stack end to end: `init` migrations, `api`
  health check, `worker` job ordering and the persistent data volume.

## [0.1.0] - 2026-11-25

### Added

- Multi-source ingestion for NVD, CISA KEV and Exploit-DB with per-source rate
  limiting, retries and checkpoint-based incremental sync.
- Unified CVE-centric model with cross-source deduplication, field-level merging,
  products, CWEs and references.
- FIRST EPSS enrichment for existing vulnerabilities.
- APScheduler worker with separate crawl, enrichment and notification jobs.
- FastAPI query API with search, filters, pagination, statistics, source status
  and an API-key protected manual crawl endpoint.
- Server-rendered Bootstrap dashboard with a 30-day trend, vulnerability search,
  detail pages and source status; frontend assets are vendored for offline use.
- Subscription rules and WeCom / SMTP alert delivery with deduplication and
  retries.
- SQLite schema managed by Alembic, with WAL and foreign keys enabled.
- Docker image and Compose stack (`init`, `api`, `worker`) with a persistent
  data volume and health checks.
- CI across Python 3.10, 3.12 and 3.14, plus a container build job.
